Ты оркестратор реализации проекта max-gate. Сам код не пишешь (кроме мелких правок при
приёмке), реализацию делает Codex с моделью `gpt-6-astra` в соседних панелях Herdr. Твоя
работа: прочитать проектные документы, нарезать реализацию на три части, поставить каждую
Codex, дождаться, проверить результат, принять или вернуть на доработку, после всего запустить
одно ревью и добиться исправления найденного. Общайся со мной по-русски, коротко.

## Что прочитать перед началом

- `CONTEXT.md`: глоссарий, используй его термины в заданиях.
- `docs/design.md`: архитектура, модель данных, потоки, границы v1, раздел 13 с порядком
  реализации и результатами шага 0.
- `docs/adr/*.md`: три принятых решения.
- `docs/research/pymax-2.4.1.md` (особенно разделы 13–16) и `docs/research/telegram-bot-api.md`.
- `spikes/pymax_smoke.py`: рабочий код входа, приёма событий, скачивания и отправки через PyMax,
  проверенный на живом аккаунте. Адаптер MAX делается на его основе.

## Секреты и данные для живых проверок

- `.env` содержит `TEL` (номер MAX), `MAX_PASS` (пароль 2FA MAX), `TG_BOT_TOKEN` (бот
  `@fsmax_bot`, режим топиков в личном чате включён, я уже отправил ему `/start`). Значения
  никогда не выводить в чат, в логи, в коммиты и в задания для Codex; Codex читает `.env` сам.
- `temp/pymax/session.db`: сохранённая сессия PyMax после шага 0. Команда `seed-account` должна
  уметь импортировать её (token, device_id, mt_instance_id, user_agent, sync), чтобы не
  запрашивать SMS заново. Если импорт не сработает, вход по SMS проводишь через меня:
  предупреди, что придёт SMS, и жди код, у нас на ввод около минуты.
- Тестовый диалог в MAX: chat `1810516` «Альтернатива-ПРО», это мой второй аккаунт, с него я
  шлю тестовые сообщения. Мой Telegram id спроси у меня, когда понадобится для `seed-account`.
- Папка `temp/` в `.gitignore`, туда складывай всё временное.

## Запреты

- Не ставить сертификаты в систему и не отключать проверку TLS. Для файлов с `fd2.oneme.ru`
  только ограниченный `ssl.SSLContext` с корнем из пакета PyMax для хостов `*.oneme.ru`
  (см. раздел 14 отчёта по PyMax и `oneme_ssl_context` в spike).
- Не менять решения из `docs/design.md` и ADR молча. Если Codex или ты видите проблему в
  дизайне, остановись и спроси меня.
- Не пушить. Коммитить можно после каждой принятой части, сообщение коммита по-русски,
  `.env` и `temp/` в коммит не попадают.

## Как запускать Codex в Herdr

Сначала убедись, что ты внутри Herdr: `test "${HERDR_ENV:-}" = 1`. Команды берутся из
`herdr --help` и `herdr agent`; идентификаторы читай из JSON-ответов, не угадывай.

Панель и агент для реализации (один агент `impl` на все три части, чтобы он помнил контекст):

```bash
PANE=$(herdr pane split --current --direction right --cwd "$PWD" --no-focus | jq -r .result.pane.pane_id)
herdr agent start impl --kind codex --pane "$PANE" -- -m gpt-6-astra -c model_reasoning_effort=medium --dangerously-bypass-approvals-and-sandbox --no-alt-screen
```

Задание и ожидание:

```bash
herdr agent prompt impl "<текст задания>" --wait --timeout 600000
herdr agent wait impl --timeout 600000        # повторять, пока состояние не idle или done
herdr agent read impl --source recent-unwrapped --lines 200
```

Если `wait` вернул `blocked`, посмотри `herdr agent get impl` и `herdr agent read impl`,
ответь агенту сам, если вопрос технический, иначе спроси меня. Если ответ агента не читается
из панели, попроси его записать отчёт в `temp/impl-report.md` и прочитай файл.

В `~/.codex/config.toml` усилие по умолчанию `low`, поэтому флаг `-c model_reasoning_effort`
обязателен: `medium` для реализации, `high` для ревью.

## Как ставить задания Codex

Astra умная, ей не нужны подробные инструкции. Задание для каждой части: одна-две фразы
о цели, список файлов-источников (`docs/design.md` с номерами разделов, ADR, отчёты, spike),
критерии приёмки и запреты выше. Не пересказывай дизайн, ссылайся на него. Проси в конце
работы короткий отчёт: что сделано, что не сделано и почему, как проверялось.

## Части

### Часть 1. Каркас, домен, адаптеры

Разделы 3, 4, 7, 11 и шаги 1–3 раздела 13 `docs/design.md`.

- `pyproject.toml` с `uv`, Python 3.12, `ruff`, `pytest`, закреплённые версии
  `maxapi-python==2.4.1` и `aiogram` 3.x; `maxgate/config.py`, `maxgate/crypto.py`,
  `maxgate/db/` с моделями и миграциями Alembic, `maxgate/cli.py` (`gen-key`, `migrate`,
  `seed-account` с импортом сессии из `temp/pymax/session.db`).
- `maxgate/domain/`: `RelayMessage`, рендер подписей и Note, экранирование текста для MAX,
  разбиение длинного текста, конвертация `elements` MAX в сущности Telegram (UTF-16).
- `maxgate/max/`: обёртка над `pymax.Client` с `ExtraConfig(relogin=False)`, `StoreProtocol`
  поверх таблицы `max_sessions` (ADR-0002), провайдеры SMS-кода и пароля на очередях,
  скачивание вложений с ограниченным SSL-контекстом, остановка отменой задачи `start()`.
- `maxgate/tg/`: aiogram-бот, проверка Owner, создание и правка Topic (цвета из раздела 6.2),
  отправка и приём медиа с лимитами.
- Юнит-тесты `domain/` и хранилища на фейках, без сети.

Приёмка: `uv run ruff check .` чисто, `uv run pytest` зелёный, `uv run maxgate migrate` и
`uv run maxgate seed-account` создают Account с импортированной сессией, а отдельная
проверочная команда (например `uv run maxgate max-check <account_id>`) входит в MAX без SMS
и печатает первые чаты.

### Часть 2. Relay и bridge

Разделы 3.1–3.3, 5, 6, 8, 9 и шаги 4–6 раздела 13 (без UI).

- `maxgate/relay/`: очереди по ChatLink, повторы, конвейеры MAX → Telegram и Telegram → MAX,
  ответы, правки, удаления, переименования, Catch-up, `/history`.
- `maxgate/bridge/`: `Supervisor`, `AccountRunner` с состояниями из раздела 3.2, внутренний
  API на `aiohttp` (ADR-0001), команды бота из раздела 9, точка входа `python -m maxgate.bridge`.
- Тесты конвейеров и движка на фейковых адаптерах.

Приёмка: тесты и линт зелёные, затем живая проверка с моим участием. Запусти bridge локально
с dev-аккаунтом, попроси меня отправить с «Альтернатива-ПРО» текст, фото, голосовое и файл,
проверь по логу и через `getUpdates` бота, что в личном чате с `@fsmax_bot` появился Topic
с этими сообщениями. Потом попроси меня ответить в Topic текстом и фото и проверь, что они
дошли до MAX (id в логе, я подтвержу с телефона). Проверь правку и удаление из MAX,
переименование Topic мной и `/mute`.

### Часть 3. UI и деплой

Раздел 10, ADR-0003, шаг 7 раздела 13.

- `maxgate/ui/`: Streamlit с паролем из env, список Account с состояниями, карточка Account
  (создание, правка настроек, мастер входа с обратным отсчётом и полем пароля 2FA, пауза,
  повторный вход, удаление, журнал событий, список ChatLink с mute).
- `Dockerfile` (один образ), `docker-compose.yml` (сервисы `bridge` и `ui`, том `/data`,
  healthcheck, порт UI на `127.0.0.1:8501`), `.env.example`, раздел README про развёртывание.

Приёмка: `docker compose up --build` поднимает оба сервиса, UI открывается и показывает
Account, живая проверка из части 2 повторяется в Docker хотя бы для текста в обе стороны.

## Ревью после трёх частей

Новая панель и отдельный агент с высоким усилием:

```bash
PANE2=$(herdr pane split --current --direction down --cwd "$PWD" --no-focus | jq -r .result.pane.pane_id)
herdr agent start reviewer --kind codex --pane "$PANE2" -- -m gpt-6-astra -c model_reasoning_effort=high --dangerously-bypass-approvals-and-sandbox --no-alt-screen
```

Задание ревьюеру: проверить весь репозиторий на соответствие `docs/design.md`, ADR и
`CONTEXT.md`, найти ошибки, гонки, потерю сообщений, утечки секретов, проблемы остановки
и переподключения, слабые места тестов. Результат записать в `temp/review.md` списком
находок с файлом, строкой, серьёзностью и предложением. Ничего не править.

Прочитай `temp/review.md`, отсей спорное, остальное передай агенту `impl` на исправление
одним заданием, после исправлений снова прогони тесты и линт и короткую живую проверку.
