# Журнал реализации max-gate

Оркестратор: Claude (сессия в Herdr). Реализация: Codex `gpt-6-astra` (medium), ревью: Codex `gpt-6-astra` (high).

## 13 сентября 2026

- Подготовка: прочитаны `CONTEXT.md`, `docs/design.md`, ADR, отчёты, spike. Установлен `uv` (в системе не было).
- Часть 1 (каркас, домен, адаптеры): поставлена агенту `impl`.
- Часть 1 принята: `ruff` чисто, `pytest` 37 зелёных, `migrate` и `seed-account --owner …` создали Account 1
  с импортированной Session из spike, `max-check 1` вошёл в MAX без SMS и показал 50 MaxChat.
  Отложено на части 2–3: очереди, Relay, Catch-up, Supervisor, InternalApi, UI, Docker.
  Живая отправка через адаптеры не проверялась (будет в части 2).
- Часть 2 (Relay и bridge): поставлена агенту `impl`.
- Часть 2 принята с одной известной ошибкой: `ruff` чисто, `pytest` 60 зелёных, bridge входит в MAX без SMS,
  API отдаёт Account 1 `active`, SIGINT останавливает чисто. Живая проверка с «Альтернатива-ПРО»
  (chat 1810516): текст, фото и файл MAX → Telegram, текст и фото Telegram → MAX, ответы и правки
  в обе стороны, удаление MAX → Telegram, `/mute` и `/unmute` работают. Не работает файл
  Telegram → MAX (`UploadError`, причина в Note не видна): исправление включено в задание части 3.
  Не проверено: голосовое (у второго аккаунта браузерный клиент MAX без микрофона), переименование
  Topic Owner (клиент Telegram не даёт переименовать топик в личном чате).
- Часть 3 (UI и деплой) плюс исправление загрузки файла: поставлена агенту `impl`.
- Часть 3 принята: `ruff` чисто, `pytest` 71 зелёный, `docker compose up --build -d` поднимает bridge (healthy)
  и ui, UI открывается по паролю и показывает Account 1. Ошибка файла Telegram → MAX исправлена:
  причина `CERTIFICATE_VERIFY_FAILED` на `fu2.oneme.ru`, загрузка переопределена в `maxgate/max/uploads.py`
  с ограниченным TLS-контекстом. Живая проверка в Docker: текст в обе стороны и файл Telegram → MAX прошли.
  Сергей попросил доработки: удаление MAX → Telegram без замены текста (значок 🗑 в начале), кнопка
  «Создать Topic» в списке ChatLink в UI, команда подгрузки истории с обязательным N, реакции в обе стороны.
- Ревью (агент `reviewer`, `temp/review.md`): 15 находок (4 high, 10 medium, 1 low). Исправлены 1, 3–14
  (plain-text отправка в MAX без markdown, поштучные повторы Catch-up, отказ повторного `/start` в другом
  Inbox, сериализация правок и удалений, содержимое ForwardLink, подписи альбома при правке, Fallback
  большого файла, очистка `payload_head` в логах, пароль 2FA без strip, уникальный `tg_bot_id`
  с миграцией 0002, TLS-политика для всех загрузок, учёт потерь при остановке, термин в README).
  Отложено: 2 (порт UI в compose, решает Сергей), 15 (логи одноразового spike). `pytest` 107 зелёных.
- Решения Сергея после живой проверки внесены в `docs/design.md`: реакции Telegram → MAX, Topic по кнопке
  из UI, `/history N` с обязательным N и MessageLink, форматирование Telegram → MAX, удаление MAX → Telegram
  как Note «🗑️ удалено!» ответом на исходное сообщение. Порт UI в compose оставлен открытым по решению Сергея
  (до появления reverse proxy).
- Часть 4 принята: кнопка «Создать Topic» и endpoint, `/history N`, реакции Telegram → MAX (живая проверка
  👍 через `get_reactions`). Зонд MAX → Telegram: сервер не присылает push о реакции собеседника (кадра 155
  нет, реакция видна только по запросу), направление не реализовано. `pytest` 116 зелёных.
- Часть 5 (форматирование Telegram → MAX, Note об удалении): поставлена агенту `impl`.
- Часть 5 принята: сущности Telegram → `elements` MAX при отправке и правке (живая проверка: типы и
  смещения UTF-16 совпали), удаление MAX → Telegram как Note «🗑️ удалено!» ответом на исходное
  сообщение. `pytest` 124 зелёных. Docker пересобран, ждёт живой проверки Сергея частей 4 и 5.
- Часть 6 принята: ошибки сервера MAX окончательные без повторов, реакции в отдельной очереди на ChatLink
  и не задерживают сообщения, при неподдерживаемом эмодзи одна попытка с переключённым U+FE0F, затем снятие
  реакции в MAX и ответ Owner. `pytest` 134 зелёных. Docker пересобран.
- 13.09.2026, редизайн UI Operator принят: `maxgate/ui/app.py` переписан на streamlit-shadcn-ui по handoff
  `temp/design_handoff_operator_ui`; InternalApiClient, `deadline()` и `invoke()` без изменений. AppTest
  управляет iframe-компонентами через session_state. Ревью (агент `reviewer`, `temp/review-ui.md`):
  6 находок (3 medium, 3 low), исправлены все, кроме Enter для отправки формы входа (ограничение
  iframe-компонентов, решение за Сергеем). `pytest` 173 зелёных, коммит 29f92d1.
- Часть 7 принята: `/history N` выполняет каждое сообщение отдельным заданием, постоянный отказ MAX при
  скачивании вложения (`error.user.file.access`) не роняет сообщение. Найдено в живой проверке Сергея.
  `pytest` 167 зелёных, коммит d28a4c8.
- Решения Сергея: `/history N` не меняется, добавляется `/reload N` (переотправка с заменой MessageLink);
  `/delete` ответом на сообщение удаляет его в MAX. Удаления Telegram → MAX без команды невозможны:
  Bot API не присылает апдейт об удалении. Часть 8 (`/reload`, `/delete`) поставлена агенту `impl`.
- Часть 8 принята на тестах: `/reload N` переотправляет последние N сообщений и атомарно заменяет их
  MessageLink; `/delete` ответом на сообщение удаляет его в MAX для всех (`delete_message(for_me=False)`),
  затем копии в Telegram и команду, собственный Echo удаления не даёт Note. Обновлены design.md 6.4, 8, 9
  и README. `pytest` 189 зелёных. Docker пересобран. Ждёт живой проверки Сергея: `/reload 5`,
  `/delete` на своём и на чужом сообщении.
- Часть 8 подтверждена живой проверкой Сергея: `/reload` и `/delete` отработали. Замечания по UI после
  живого просмотра (кнопки secondary вместо ghost, разделители в списке чатов, действия строки справа)
  поставлены агенту `impl2`; прежний агент `impl` завершён при 78 % контекста.
- Правки UI после живого просмотра приняты: «Выйти», «Logout», «Mute»/«Unmute» в варианте secondary,
  разделители между строками «Чаты MAX», «Создать Topic» и «Mute» одной группой справа (на 390 px группа
  переносится целиком). `pytest` 189 зелёных, Docker пересобран.
- Вторая порция правок UI по скриншоту Сергея принята: пилюля Bridge вплотную к «Выйти», действия карточки
  Account одной группой у правого края, «Сохранить настройки» в заголовке карточки справа, «Удалить Account»
  у правого края. `pytest` 189 зелёных, Docker пересобран.
