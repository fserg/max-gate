# Session MAX хранится в нашей базе зашифрованной через собственный StoreProtocol

PyMax по умолчанию пишет Session (токен входа, device_id, user-agent, sync-маркеры)
в собственный SQLite-файл открытым текстом, по одному файлу на аккаунт. Мы реализуем
документированный интерфейс `pymax.session.StoreProtocol` поверх таблицы `max_sessions`
в нашей базе и шифруем токен тем же ключом Fernet, что и токены ботов. Так секреты лежат
в одном месте, база бэкапится одним файлом, а на диске нет незашифрованных токенов.

## Considered Options

- Штатные файлы PyMax в томе `/data`: ноль кода, но токен на диске открытым текстом
  и второй артефакт для бэкапа.

## Consequences

- При обновлении PyMax нужно сверять модель `SessionInfo` с нашей таблицей; версия PyMax
  закреплена точно, обновляется осознанно.
- Токены TCP-клиента и Web-клиента PyMax не взаимозаменяемы: если в v2 появится вход по QR,
  у Session потребуется поле транспорта.
