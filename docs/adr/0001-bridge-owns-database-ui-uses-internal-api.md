# bridge владеет базой данных, UI работает через внутренний HTTP API

Вход в MAX через PyMax не разбивается на независимые шаги: клиент держит TCP-соединение и ждёт
SMS-код внутри `start()`, а Streamlit перезапускает скрипт страницы на каждое действие
и не может надёжно удерживать живой asyncio-клиент. Поэтому вход, как и всё остальное общение
с MAX и Telegram, живёт в процессе `bridge`, а он же остаётся единственным писателем в SQLite.
UI получает маленький HTTP API (`aiohttp`, токен из env) и не открывает файл базы вообще.

## Considered Options

- Общая база и опрос изменений из `bridge`: проще на вид, но вход по SMS всё равно нужно
  вести в `bridge`, получились бы два канала связи вместо одного.
- Один процесс со Streamlit и мостом в разных потоках: падение или перезапуск UI ронял бы
  все Account.

## Consequences

- Когда `bridge` лежит, UI только сообщает об этом; управлять нечем, и это честно.
- Любая новая функция UI требует эндпоинта в API.
